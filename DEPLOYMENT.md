# Deploy MediShop: Supabase → Render → Vercel

The repository is already connected to GitHub. PHP runs on Render, data and images live on Supabase, and Vercel forwards the public URL to Render. Vercel is a proxy in this setup because the HTML is generated by PHP rather than a separate frontend app.

## 1. Create the Supabase project and tables

1. In [Supabase Dashboard](https://supabase.com/dashboard), create a project and save its database password.
2. Open **SQL Editor → New query**. Paste the contents of `database.pg.sql`, then click **Run** once. Do not paste the MySQL `database.sql` here.
3. In **Table Editor**, confirm `users`, `categories`, `medicines`, `cart`, `orders`, `order_items`, and `payments` exist. `categories` and `medicines` should contain sample rows.
4. The SQL enables Row Level Security with no browser policies. The PHP server connects to PostgreSQL directly; it does not use the Supabase Data API for shop tables.

If you already have real MySQL users and orders, `database.pg.sql` does not transfer them. Import those data separately, keeping IDs and resetting identity sequences afterward.

## 2. Create a Supabase Storage bucket

1. Open **Storage → New bucket**.
2. Set the bucket name to `medishop-images` and make it **Public**. The app displays profile and medicine images on public web pages.
3. Optionally restrict MIME types to `image/jpeg` and `image/png`, with a 2 MB file limit. The PHP code also validates these.
4. Open **Project Settings → API Keys**. Create/copy a **secret key** (`sb_secret_...`) for Render. It must never go in GitHub or Vercel.
5. Copy the **Project URL** (`https://PROJECT_REF.supabase.co`). This is for Storage, not the PostgreSQL host.

The application sends the secret key in the `apikey` header from Render. It never sends the key to the browser.

## 3. Copy PostgreSQL connection details

Open **Connect → Session pooler** in your Supabase project. Copy each value from the displayed connection string:

| Render variable | Value |
| --- | --- |
| `DB_DRIVER` | `pgsql` |
| `DB_HOST` | Session pooler hostname shown by Supabase |
| `DB_PORT` | `5432` for session mode |
| `DB_NAME` | `postgres` |
| `DB_USER` | Session pooler username, usually `postgres.PROJECT_REF` |
| `DB_PASS` | Your project database password |

Use **Session pooler**, not Transaction pooler. The adapter uses connection-local `LASTVAL()` after inserts. Copy the hostname and username exactly; do not assemble them from the project URL.

## 4. Create the Render Web Service

1. Open [Render Dashboard](https://dashboard.render.com/) → **New → Web Service**.
2. Connect this GitHub repository. Choose branch `main`, language **Docker**, and repository root as the root directory.
3. In **Environment**, add the six `DB_*` variables above and:

| Render variable | Value |
| --- | --- |
| `APP_ENV` | `production` |
| `REMEMBER_SECRET` | A random 64-character hex string (command below) |
| `SUPABASE_URL` | Supabase Project URL |
| `SUPABASE_SECRET_KEY` | Secret key from Project Settings → API Keys |
| `SUPABASE_STORAGE_BUCKET` | `medishop-images` |

Generate the remember secret on your computer:

```powershell
& 'C:\xampp\php\php.exe' -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

4. Deploy. `Dockerfile` starts Apache on port `10000`; Render's default `PORT` is `10000`.
5. Open the `https://YOUR-SERVICE.onrender.com/` URL. Check the home page and sample medicines, then register/login and make a sample order.
6. After registering an account intended to be the admin, open Supabase **SQL Editor** and run:

```sql
UPDATE users SET role = 'admin' WHERE email = 'your-admin-email@example.com';
```

Sign out and sign in again to refresh the role stored in the PHP session. Public registration always creates a customer.

## 5. Put Vercel in front

1. Edit `vercel-proxy/vercel.json`: replace both `https://REPLACE-ME.onrender.com` values with the actual Render URL.
2. Commit and push that file to GitHub.
3. In [Vercel Dashboard](https://vercel.com/dashboard), import the same GitHub repository as a new project.
4. Set **Root Directory** to `vercel-proxy`, **Framework Preset** to **Other**, and leave **Build Command** empty.
5. Deploy. Open the Vercel URL and repeat the register/login/cart/order test. The browser URL should remain on Vercel while the requests reach Render.

Keeping the Vercel root at `vercel-proxy` prevents PHP source files from being deployed as static assets there.

## 6. Final checks

- Upload a profile photo and a medicine image; confirm both still load after a Render redeploy.
- Test customer registration, login, search, cart, checkout, order cancel/reorder, and admin order review.
- Check Render logs if a page fails. A DB connection error usually means the pooler host/user/password or `DB_DRIVER` differs from the copied values.
- If an image upload fails, check that the public bucket exists and `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, and `SUPABASE_STORAGE_BUCKET` are correct.
- PHP file sessions on Render may end after a service restart or deploy, so users may have to sign in again. Orders and images remain in Supabase.

No password or secret should be added to tracked files or Vercel settings. The Vercel project only proxies requests; Render holds all server secrets.
